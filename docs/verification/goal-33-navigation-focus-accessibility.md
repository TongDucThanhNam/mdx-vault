## File-tree top-gap follow-up

The regression was not a row-height or virtualization offset mismatch: the custom icon `spriteSheet` inserted a second top-level SVG into the tree shadow root without dimensions. That SVG occupied **129.875px** above the virtualized wrapper. Its root is now `aria-hidden` and `width="0" height="0"`, like the library's own sprite; no negative margin is used. `tests/goal33-navigation-polish.test.ts` locks down the zero-size sprite root.

`.tmp/goal33_tree_gap_probe.log` records an Electron geometry matrix: comfortable/default rows are 28px, compact rows are 24px, and for both extension settings the first `assets` row begins at **y=80px**, matching the Vault header bottom at **y=80px** (gap **0px**). The same 0px measurement held after folder collapse, re-expand, and scroll-to-bottom-and-back in all four combinations. The custom sprite measured 0px high. The entire 1920×1080 visual set was refreshed; specifically `light-1920x1080-no-note-selected.png` and `dark-1920x1080-dns-outline.png` show the repaired top edge. `light-1920x1080-compact-file-tree.png` is the compact-density capture. `.tmp/goal33_visual_followup.log` records the recapture run.
